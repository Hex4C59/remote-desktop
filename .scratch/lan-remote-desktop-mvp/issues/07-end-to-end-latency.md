# 07: 测量软件处理耗时与操作到反馈帧耗时

**What to build:** 测量 Windows 本地采集/帧处理/媒体提交阶段耗时，以及控制端发送操作到软件观察到对应反馈视频帧的耗时。物理画面显示延迟和操作反馈延迟延期，不是本任务的软件指标。

**Blocked by:** 04: 输入字符与终端必需按键, 06: 显示实际帧率和码率

**Status:** ready-for-agent

- [ ] 探索并验证真实桌面操作与反馈视频帧的唯一编号关联，明确控制端实际可观测的结束位置；先验证可行性，不预先承诺实现方案。若无法可靠关联，记录阻塞，不以 DataChannel 回显、Windows 日志或无关帧代替。
- [ ] 使用 Windows 单调时钟测量本地阶段，明确采集调用/取得帧、转换与缩放、媒体提交等可观测边界；媒体提交不等于编码完成。起终点处于同一控制端单调时钟的“操作到反馈帧耗时”不直接相减跨设备时间戳。
- [ ] 预先固定场景、样本数、预热、失败/超时保留规则，保存原始样本、版本、同会话统计关联和可复算摘要；记录测量设施开销、缺失阶段和结束位置的局限。
- [ ] 完成正常配对真实桌面会话验证和相关输入/结束/手动重连回归。软件结果不称为物理屏幕端到端延迟，不包含尚未观察的触摸前段或屏幕呈现阶段。

物理测量延期：原定义的画面显示延迟、操作反馈延迟仍未验收，不能用本任务完成状态或软件代理指标将其勾选为通过。
