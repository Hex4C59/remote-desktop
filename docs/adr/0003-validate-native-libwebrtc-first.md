# 优先验证原生 libwebrtc，设置构建与互通检查点

在一个月的期限和已确认的基础设施复用边界下，决定先验证 Windows C++ 与 Android Java 接入原生 libwebrtc 的路线，复用视频媒体链路和 DataChannel。相较于自行连接编解码器与较轻传输库，这一选择优先减少视频接收与网络反馈闭环的集成责任；代价是 libwebrtc 的构建、版本与平台接入复杂度。

先给构建及真机互通验证 2–3 个工作日：两端能够重复构建，局域网测试画面可显示，控制消息可回传。通过后再展开功能；未通过则根据具体阻塞重新评估，不自动改换路线。这是候选路线的验证决定，不保证任何特定编解码器、硬件加速或性能指标已可用。

用户同意配置 Windows 远程开发访问，以建立重复构建、运行与日志回传流程。实际访问方式与工具链须先核查。资料依据见[技术路线调研](../technical-options.md)。
