# 文档写作示例

技术黑话常见于标题、链接文字和正文中的内部叫法。读者如果必须先问“这个词在你们项目里是什么意思”，才能知道这段文字讲什么，就把那个叫法改写成读者能理解的内容。写操作时，说明谁用什么设备、做什么、会看到什么结果。写验收时，说明在哪些条件下检查什么结果。

## 001 的实际改写

| 用在哪里 | 原来的写法 | 改成的写法 | 读者能直接知道什么 |
| --- | --- | --- | --- |
| 第一阶段的目录名 | `001-lan-vertical-slice`（局域网垂直切片） | `001-android-controls-windows-over-lan`（Android 手机在局域网远控 Windows 电脑） | 谁控制谁，两台设备在哪种网络下工作。 |
| 架构总览里的链接 | 里程碑规格 | 交付内容和验收要求 | 点开能查到要做什么、怎样算达标。 |
| 001 的开头 | 里程碑级规格 | 本文说明第一阶段（M1）要交付什么，以及怎样用手机和电脑验收。 | 文档讲的是整个阶段，并会说明用哪些设备验收。 |
| 任务清单里的要求 | 先完成并评审功能级规格、方案和任务。 | 先为各项功能编写规格、方案和任务清单，再提交评审。 | 每项功能要准备哪些材料，准备好后要提交评审。 |

001 所说的验收可以用具体动作讲清楚。让 Android 手机和 Windows 电脑接入同一局域网，完成配对，在电脑上同意本次连接。确认手机能显示电脑的实时桌面，并能用触控和键盘操作电脑。记录操作延迟，检查连续使用一小时是否稳定。[001 文档](increments/001-android-controls-windows-over-lan/spec.md) · [架构总览](architecture/overview.md)

## 怎样写必要的技术名词

开发规格中，把「接口契约」写成「接口约定」。面向普通读者的标题可以写「怎么调用、会返回什么」。例如，调用屏幕采集接口时，先提供一块存放画面的缓冲区并指定最长等待时间。采集成功后，画面写入缓冲区。超过等待时间时，接口返回超时错误。[屏幕采集](architecture/platform-abstraction.md#3-屏幕采集)

「幂等」（读作 *mì děng*）指同一个操作执行一次和重复执行多次，最终效果一样。写到断开远控时，可以把「断开操作是幂等的」改成「如果会话已经断开，再次请求断开时，会话保持断开状态。」

面向使用者时，可以写“在手机上查看电脑的实时桌面”。开发文档如果需要指明采用哪个 Windows 接口，可以写“使用 DXGI Desktop Duplication（Windows 提供的桌面画面采集接口）获取画面”。这样读者既知道这个接口是干什么的，开发者也能找到它的正式名称。
