## 合成 I420 帧视频源

- 无需摄像头或 test 框架。候选自定义 `SyntheticSource : VideoTrackSource`，基类构造 `VideoTrackSource(false)`，持有 `VideoBroadcaster`，覆盖 `source()` 返回 broadcaster，通过 `OnFrame(frame)` 注入。可参考官方最小 fake 的结构，但应用不要依赖 `pc/test` 目标。[pc/video_track_source.h](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/pc/video_track_source.h)、[pc/test/fake_video_track_source.h](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/pc/test/fake_video_track_source.h)
- 每帧 `I420Buffer::Create(width,height)`，按各 plane 的 stride 填 Y/U/V，再 `VideoFrame::Builder().set_video_frame_buffer(buffer).set_timestamp_us(monotonic_us).set_rotation(kVideoRotation_0).build()`；提交后不再修改仍被下游引用的 buffer。单调时间与移动图案属于候选测试设计。[api/video/i420_buffer.h](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/api/video/i420_buffer.h)、[api/video/video_frame.h:102](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/api/video/video_frame.h#102)
- 更完整的采集适配基类已经移到 `api/video/adapted_video_track_source.h`；其 `AdaptFrame`/`OnFrame` 可在任意线程调用，sink 增删须同一线程。若选该基类还需实现剩余 source interface；它不是可直接实例化的生成器。[api/video/adapted_video_track_source.h:32](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/api/video/adapted_video_track_source.h#32)
- `factory->CreateVideoTrack(source, "desktop")` 的参数顺序是 **source 在前**；随后 `pc->AddTrack(track, {"desktop-stream"})` 并检查 `RTCErrorOr`。[api/peer_connection_interface.h:1611](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/api/peer_connection_interface.h#1611)、[examples/peerconnection/client/conductor.cc:523](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/examples/peerconnection/client/conductor.cc#523)

## SDP、ICE、DataChannel

- `RTCConfiguration` 使用 Unified Plan；局域网候选可以先不配置外部 ICE server，但仍要交换 SDP 和 ICE。用 `PeerConnectionDependencies(observer)` 调 `CreatePeerConnectionOrError(config,std::move(deps))`。[examples/peerconnection/client/conductor.cc:240](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/examples/peerconnection/client/conductor.cc#240)、[api/peer_connection_interface.h](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/api/peer_connection_interface.h)
- 为简化首轮，Windows 为唯一 offerer：先 AddTrack、`CreateDataChannelOrError("control", &init)`，再 CreateOffer。CreateOffer 返回描述后 SetLocalDescription；发送 SDP，处理 `OnIceCandidate` 并交换 candidate。Android SetRemoteDescription 成功后 CreateAnswer→SetLocalDescription→回传，Windows SetRemoteDescription(answer)。这是候选信令时序，不实现 glare/重新协商。[api/peer_connection_interface.h:992](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/api/peer_connection_interface.h#992)、[api/jsep.h](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/api/jsep.h)
- 优先使用接收 `unique_ptr<SessionDescriptionInterface>` 与 `SetLocalDescriptionObserverInterface` / `SetRemoteDescriptionObserverInterface` 的新接口；回调可能在方法返回前完成，不应假定异步延后一拍。候选将早到 ICE 缓存到远端 SDP 成功设置后再 AddIceCandidate，记录操作错误。[api/peer_connection_interface.h:1040](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/api/peer_connection_interface.h#1040)
- `DataChannelObserver` 必须实现 `OnStateChange`、`OnMessage`；RegisterObserver 后等 `kOpen` 再 Send，结束先 UnregisterObserver。默认回调在 signaling thread，明确禁止在 observer 回调里重入 WebRTC API，应投递任务。初原型可靠有序控制消息，附序号与回显；不发送视频到 DataChannel。[api/data_channel_interface.h:98](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/api/data_channel_interface.h#98)

## Android 接收 wrapper 所有权复核

- `PeerConnectionObserverJni::OnTrack` 把 Java transceiver 存入 `rtp_transceivers_` 的 `JavaRtpTransceiverGlobalOwner` 后调用 Java observer；owner 析构调用 Java `RtpTransceiver.dispose()`。`PeerConnectionObserverJni` 是默认析构，成员 vector 随之销毁。[OnTrack](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/sdk/android/src/jni/pc/peer_connection.cc#474)、[owner 定义](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/sdk/android/src/jni/pc/peer_connection.h#116)、[owner 析构](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/sdk/android/src/jni/pc/rtp_transceiver.cc#94)
- 正常 Java `pc.dispose()` 最终调用 `freeOwnedPeerConnection` 删除 `OwnedPeerConnection`；其析构先释放 native peer connection，再析构所持 observer，从而清理上述 callback wrappers。应用不应主动 dispose 库拥有的 callback transceiver，也不能把它当作跨连接存活的对象。[native 清理](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/sdk/android/src/jni/pc/peer_connection.cc#527)、[Java 清理](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/sdk/android/api/org/webrtc/PeerConnection.java#1294)
- `pc.getReceivers()` 每次先 dispose 上次返回的 receiver wrappers，再构造新 wrappers。`RtpReceiver.dispose()` dispose cached track；`VideoTrack.dispose()` 移除该 wrapper 注册的全部 sinks。因而反复 getReceivers 可导致此前附加的视频 sink 被移除；保留 Java 引用并不能阻止这种显式 dispose。[getReceivers](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/sdk/android/api/org/webrtc/PeerConnection.java#1049)、[receiver dispose](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/sdk/android/api/org/webrtc/RtpReceiver.java#76)、[track dispose](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/sdk/android/api/org/webrtc/VideoTrack.java#69)
- **候选首原型流程合理**：Android SetRemoteDescription 成功后向应用自有单线程 executor 排任务；先检查会话 generation/closing 状态，再仅调用一次 getReceivers，筛选非 null VideoTrack 并 addSink 到已经初始化的 renderer。保存 receiver/track 引用，后续状态刷新不再调用 getReceivers。它们的释放由 pc.dispose 负责，应用不另行 dispose 这些 wrappers。此建议针对单连接、单视频、无重新协商的探针；仅源码推导，尚未运行。
- 在同一 executor 串行清理：阻止新 attach 任务→对保存的有效 track 执行 removeSink→pc.dispose→清空应用引用；UI 主线程的 renderer.release 与 EGL 清理必须等待解绑完成。不能从 WebRTC observer 回调直接 pc.dispose，Java 文档明确要求先退出回调栈；也不要让过期 SDP 成功回调在关闭后再次 attach。[dispose 回调限制](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/sdk/android/api/org/webrtc/PeerConnection.java#1286)、[renderer 生命周期](https://webrtc.googlesource.com/src/+/a3553f1c82a5580c91ad1f82baab4b11ed4b34b6/sdk/android/api/org/webrtc/SurfaceViewRenderer.java#94)
