## 候选方法与起终点

使用**一台外部相机的一段原始录像**同时观察两块物理屏幕，反馈实验还必须清晰看到手指。相机是共同时间基准；不相减 Windows/Harmony/Android 的时钟，不使用 HDC 截图完成时间、SSH 返回时间或任何软件回调作为显示终点。方法待短试拍验证可读性后才能定为实际可用。

| 指标 | 起点可观测事件 | 终点可观测事件 |
| --- | --- | --- |
| 画面显示延迟 | Windows 实体屏幕固定目标行首次完整可辨认本次唯一事件 ID 及其条纹 | 平板远程视频区域首次完整可辨认相同 ID 及条纹 |
| 操作反馈延迟 | 手指在平板应用 Enter 按钮上**首次接触**屏幕的动作（最后明确未接触至首次明确接触） | 平板远程视频内首次完整可辨认真实 PowerShell `lf` 执行产生的新 ID 及条纹 |

反馈起点包含用户触碰至松手所用时间。另标注松手区间作为解释材料，不把它悄悄替换为起点；不从按钮本地高亮推断接触时刻。侧斜角须能判读接触，手指不得遮挡目标行。接触看不清的样本标为 unreadable。显示起点是可辨认新内容而非首个任意像素翻转，两个屏幕采用相同完整 ID 判据；刷新扫描会影响两者达成可辨认状态的时刻，必须记录局限。

终端输出、采集帧、SendInput、解码、renderer 提交、RTT、回显和任务06统计窗口都不替代上述光学事件。终端日志只用于身份/顺序核对。当前脚本不做自动视觉检测；以后若加自动候选提取，单独保存候选、算法/版本与人工修订，所有采用的边界帧须回看原画面。

## 采样前固定方案 v1

每类2轮，每轮3个预热事件 + 10个正式事件，共每类20个正式样本及6个预热事件。两个实验可在同一正常授权会话依次执行；另建新会话必须新实验 UUID、新目录和新终端。20个样本用于检验完整测量流程并描述短时分布，不支持 p95/p99 或稳定性承诺。不设置性能通过阈值。

1. 正常入口地址/新口令配对后，先确认解码尺寸、统计 UUID、持续视频和专用终端前台；等待至少30秒。拍摄前固定两屏摆放、焦点、录像模式、刷新率/缩放和终端字体。拍10秒试片验证 ID、接触动作和统计区都可辨认。试片独立编号，不进入正式统计。
2. 画面实验：在真实 PowerShell 内运行 `ld`，每轮先等待10秒，再每5秒改变一次目标行；前3个 `W` 为预热，随后10个 `S` 为正式。第二轮重复同样流程。Windows 画面由正常桌面采集和视频链路到平板，没有合成视频替代。
3. 反馈实验：通过平板草稿输入 `lf`，发送文本；确认专用终端前台且实际命令行为 `lf`，然后拍到手指点击应用 Enter。之后每次先按应用 Up 调出 `lf`，核对真实终端命令，再点击 Enter。每次至少隔5秒，上一结果已可辨认后才继续；每轮13次，前3次预热。两轮间停10秒。不要按软键盘本地换行代替应用 Enter。
4. 5秒没有目标结果就记 timeout，并保留后续晚到结果；不要立即重发。显示序列仍有唯一编号，晚到/遗漏可追溯。反馈遇到超时先停止输入，查明是否执行，禁止用相同编号重试。失焦、管理故障或会话结束立即停；尚未执行项为 not_run，不能与失败混算。补测使用新实验 ID 并说明原因，原记录不删除。
5. 排除条件预先限定：两屏/手指不在画面、目标被遮挡或模糊、事件身份不唯一、录像缺段/时基不明、前台干扰、错误命令、非正常授权会话。分别标 unreadable、excluded 或 failed 并写原因。慢样本、冻结、超时不能因为结果不好而排除。预热保留但不参与正式中位数。

准备脚本：[终端场景](../../scripts/windows/show-latency-scene.ps1)、[录像索引/区间分析](../../scripts/latency/analyze.py)。终端脚本只定义真实 shell 命令，不注入输入、不接管授权、不修改应用。要求新的经典控制台；使用任务04终端设施时保留 Consolas32、大字宽窗口、QuickEdit关闭。每个事件 ID 含完整实验 UUID、实验类别、轮次及 W/S 序号。新会话须关闭旧终端重新加载；禁止只替换 UUID 继续旧计数。`stop.request` 让下一次场景输出拒绝执行；结束时关闭自建终端，清理该会话所有设施。

在新专用 PowerShell 中点源（实际 UUID 必须换成当次值，下面仅示意）：

```powershell
. .\show-latency-scene.ps1 -Experiment <experiment-uuid> -SessionUuid <statistics-uuid> -OutputDirectory <new-private-directory>
```

发送前自动驱动仍须调用任务04—06已验证的前台/可见目标保护，不能只依赖脚本在命令执行后的检查。人工操作也须每次核验两屏中的专用终端及命令；发现本地切窗就停，不自动抢前台。

## 一次拍摄操作说明（以后恢复时执行，当前不执行）

1. 平板放在 Windows 显示器旁；另一部手机横向固定，让两块屏幕目标行尽量处于录像相同高度，同时看清平板 Enter 和手指。不要拍摄口令；取景避开私人窗口。尽量锁定焦点/曝光，记录相机型号和设置；原生30/60/120fps均可，不插帧、不使用无法解释原始拍摄时基的慢动作导出。
2. Agent先完成网络快照、必要部署、正常配对、专用终端和统计 UUID 记录。用户录制短试片，确认拍到屏幕内容和接触动作。若不可辨认，调整摆放后重新试片并保存失败试片索引。
3. 固定方案与版本后开始连续录像，先拍约5秒静态的实验/会话标识与统计区，再执行上节 `ld`；完成后保留约5秒。反馈片按上节操作两轮，每次实际接触/松手都在画面中，最后也保留5秒。
4. 保存手机原始视频（不裁剪、不变速、不经聊天软件压缩）到忽略目录 `.local/task07/recordings/`。原件只读保留，计算 SHA-256；裁剪和提帧另存。如有分段，记录每段起止和缺口，跨片段没有连续时基的事件不可用于精确相减。
5. 完成后正常“结束会话”，回收同一 UUID 的统计 JSONL，验证发送端结束与平板非实时结束页；再正常手动新配对确认新 UUID、无旧输入/事件/统计。按快照恢复 WLAN、热点和显示设置，逐项检查自建进程、规则、任务、超时覆盖；未确认项明确留空。

## 帧时间、判读和误差

索引工具读取原文件逐帧 PTS，不以 `帧号 / 标称fps` 计算。保存编码流时基、平均/标称帧率、每帧 PTS、帧间距、解码像素 MD5；检测间距变化、超过中位间距1.5倍的疑似缺帧和连续全帧相同候选。后两项不是确定丢帧/重复帧：静态场景本来可能相同，相机重复旧帧也可能保留规则 PTS；须人工回看，必要时用动态试片检查。非递增/缺失 PTS 直接拒绝分析。

标注零起算的 `last_absent` 与 `first_present`，包含模糊过渡时可跨多帧。设起点区间 `[a,b]`、终点区间 `[c,d]`，PTS 包络为 `[c-b,d-a]`。保留跨同一相机帧的重叠区间及可能负下界，不强行截为0。工具中的小数是 PTS 算术结果，**不是物理测量精度**；最终人工摘要按相机分辨率向外取整、同时报告帧区间，不能报虚假的单一毫秒值。30fps每帧约33ms，两个起终点都各夹在相邻帧时，包络宽度通常约两帧。

还须独立记录曝光长度/未知、滚动快门读出/未知、屏幕刷新模式、扫屏条纹和人工判读分歧。PTS 不保证是目标所在传感器行的曝光时刻。尽量将两个目标行摆在相同相机高度；没有经过确认的曝光/读出界时，`additional_optical_uncertainty_ms=null`，扩展总区间为空，明确**只有帧采样包络，物理总误差未定界**。不能凭“30fps”自动认定总误差为±33ms。若确认保守光学误差界 M，则整体区间扩为 `[c-b-M,d-a+M]`，记录来源、适用条件、校准文件及哈希。相机时钟速率/慢放变换不明时不把 PTS 秒冒充真实秒；先核验原速并记录依据。

屏幕刷新和从模糊到可读的视觉阈值限制测量解释，不是要从结果中扣除的处理阶段。无跨设备时间戳相减，因此无需假造 NTP 同步、时钟漂移或对称网络假设；同次统计关联也不用于换算时钟。重复标注一遍全部正式边界，保留初稿和修订；无法取得第二独立判读者时明确是同一人复读，分歧扩大区间或标无法判读。

```json
{"last_absent": 100, "first_present": 102, "reviewer": "actual-reviewer", "raw_frames_reviewed": true, "rule": "entire unique event ID and stripe readable"}
```

反馈起点换成实际接触规则。工具不会自动判读动作，不会生成物理屏幕证据。任何 `valid` 行必须有两端原画面复核、溯源和统计关联字段。非 valid 行必须有原因。`annotation_method` 为 `manual` 或 `automatic_reviewed`，保留自动初值文件。失败/超时行也可附起点或晚到终点，不能改写成有效快速样本。

摘要分指标报告正式计划数、执行数、valid/failed/timeout/unreadable/excluded/not_run 数量、中位数区间、范围包络，并保留按轮汇总。当前每类计划20个正式样本，只报中位数与范围，不报 p95/p99；超时存在时必须说明有效样本摘要受截尾影响，不能代表所有尝试的分布。未知光学误差不能只丢掉该样本计算其余样本的“总误差摘要”。当前真实样本0，两类中位数、范围、分位数均 null。

## 同会话任务06统计与工具开销

录像同时拍到平板统计区的会话前缀和 seq，回收 Windows 写入的完整 UUID JSONL。每个事件标注其前后可读的 seq，按完整 UUID+seq 找原记录，分别附实际解码尺寸、解码 fps、接收负载 kb/s、冻结累计/时长、状态、实际窗口和送达缺号。前缀必须在本次文件中唯一且由配对记录确认完整 UUID；不只凭前缀猜会话。统计区看不清时仅能做到片段/会话级关联，精度明确降低；日志未送达的样本写缺失，不能补造。

关联是“录像中可见统计窗口覆盖/邻近该事件”，精度通常是一整个实际统计窗口及UI显示滞后，不是视频帧级时钟同步。不同时间的软件时间戳不直接与相机相减。**解码 fps 不是物理屏幕显示帧率**，库冻结是回顾性解码元数据统计，不是完整物理冻结探测。

外部录像不向产品注入流量；终端脚本每事件一次 JSONL 写入在输出调用之后，仍可能影响后续调度/磁盘，实际开销待测。若复用任务04观察器，其100ms控制台读取和变化落盘也有开销；正式采样前选择并固定是否启用，不能称零开销。保持任务06统计频率不变，记录文件尺寸和采样数。正式录像期间不做HDC连续截图、屏幕录制或不断发送管理输入；记录所有不可避免的管理动作和异常。不得将测量设施开销混为产品稳定性能。
