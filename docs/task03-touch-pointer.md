# 任务03：触屏定位并点击终端验收

2026-09-26完成。Android 控制端通过正常地址和临时配对口令入口连接，在实际视频区域轻触并松手，Windows 被控端将指针定位并执行左键点击。实现说明见[输入协议](pointer-input.md)，结构化结果见[验证摘要](evidence/task03-touch-pointer.json)。

## 真机结果

最终运行 `bdbf5def0f5f4c59994d10c0cfddb838` 使用最终 Windows 构建和 Android APK，完整脚本退出码为0：

- 2560×1440 主显示器桌面缩放为1280×720视频，手机实际视频区域为2059×1158，左右有留边。目标 `(957,732)` 实际指针为 `(957,733)`；第二目标 `(1586,578)` 实际为 `(1587,578)`，误差均不超过1个桌面像素。
- 手机首次点击使专用终端从未激活变为激活。Windows 控制台可能吞掉激活窗口的第一次点击，因此在已激活终端内另行点击，独立 `ReadConsoleInput` 观测到真实 DOWN/UP；第二目标也产生完整一对事件。终端未执行任何由测试输入的 shell 命令。
- Agent查看完整手机截图及终端细节，确认点击前终端显示 `INACTIVE`，点击后显示 `ACTIVE`，并能看到与 Windows 事件一致的 `WINDOWS DOWN/UP` 及两处坐标。不是仅依据 DataChannel 回显或发送端日志判定成功。
- 错误凭据在配对阶段被拒绝，无桌面首帧；触摸其空白区域后，Windows 光标、终端事件数和按钮释放状态均未改变。
- 分别点击左右留边，以及在视频内拖动：Windows 光标和事件数均未改变，左键未保持按下。
- 只有触摸按下、尚未松手时没有远端按键按下；此时切后台，授权会话结束，被控端正常退出。返回同一 Android 进程的旧界面后再点击，不产生 Windows 输入；未出现 Java 崩溃。

脚本以 Windows 的物理指针坐标、实际前台窗口、控制台输入事件和按钮状态作为外部观测，并在发送点击前确认目标确实位于专用终端上。手机截图补充显示侧证据。截图、SDP及原始运行日志仅保存在忽略的本地目录；公开摘要只记录运行编号、结果和文件哈希。
