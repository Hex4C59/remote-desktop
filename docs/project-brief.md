# 项目访谈记录

## 已确认的目标与约束

- 核心场景：用户外出后通过手机连接家中电脑编程。
- 主要目的：校招求职展示，目标岗位为 RTC 实时通信工程师。
- 第一版平台：Android 控制端、Windows 被控端。
- 人员：用户一人，加一个 Agent 辅助。
- 基础：掌握 C++ 基础，暂无音视频经验。
- 时间：每天 4–5 小时，期望一个月完成。
- 学习顺序偏好：先完成可运行项目，再深入学习。
- 实现边界：不直接修改现成远程桌面项目；自己组织核心流程，允许复用或修改基础设施，复用编码、加密等成熟基础库。
- 操作需求：手机显示 Windows 桌面的视频画面，在画面中操作终端进行编程；不是仅传输命令与文本结果的远程终端。
- 运行前提：Windows 保持开机、提前登录，由用户手动启动被控程序；第一版不要求登录界面控制、锁屏控制或开机自启。
- 资源：具备 Windows 电脑和 Android 真机，暂无公网服务器。
- 阶段安排：本月完成局域网流程并测清性能，公网连接作为后续目标。
- 媒体范围：第一版传输桌面视频，不传声音。
- 展示要求：可操作的画面传输，以及延迟、码率、帧率和网络变差时的表现；具体指标定义、目标和测试条件待确认。
- 输入范围：英文、数字、符号，Enter、Tab、方向键和 Ctrl+C，配合触屏定位；中文输入后续处理。
- 连接方式：允许手动输入电脑地址；第一版不做设备发现、账户系统、文件传输或剪贴板同步。
- 并发与显示范围：只控制一个显示器，同时只允许一部手机连接。
- 初步性能目标：正常局域网下 720p、30 FPS，连续操作 10 分钟；通过原型验证可行性。
- 测量范围：分别测量画面变化到手机显示、手机输入到显示反馈的延迟，并记录实际码率与帧率；延迟阈值在链路与设备验证后确定。
- 连接授权：Windows 程序启动后显示临时配对口令，手机输入地址和口令连接，无需注册账户；具体认证与加密机制在选型时确定。
- 断线行为：手机断网、退出或切到后台后结束当前连接；回到前台手动重连。断线时释放远端按键状态，第一版不做后台保活和自动重连。
- 弱网实验：分别测试带宽受限、延迟增加和丢包，记录画面流畅度、操作延迟与恢复情况；选择一个主要瓶颈，完成优化前后对照。实验参数在基线测量后确定。
- 候选路线验证：接受优先验证原生 libwebrtc，Windows 使用 C++，Android 使用 Java 接入视频显示与输入，媒体链路及 DataChannel 复用基础设施。先用 2–3 个工作日检查构建与真机互通，若未打通则依据具体阻塞重新评估，不自动替换路线。
- Windows 开发协作：用户愿意配置远程开发访问，使 Windows 保持可访问，建立可重复的构建、运行与日志回传流程。当前已通过SSH/SFTP建立构建与日志回传，详见第一阶段验证记录。
