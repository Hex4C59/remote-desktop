# Windows 控制端渲染表面

status: approved
approved-by: Hex4C59, 2026-11-24

## 1. 范围

为 [001 M1](../001-android-controls-windows-over-lan/spec.md) 的 Windows 控制端提供单窗口 SDR 视频呈现。定义解码帧借用、尺寸变化、错误恢复与首帧确认。编解码选型、网络发送和输入信令由各自规格定义。

## 2. 接口约定

公共类型及签名的唯一定义见[平台抽象 §7](../../architecture/platform-abstraction.md#7-渲染表面控制端)。UI 线程创建、调用和销毁 `RenderSurface`。Windows 实现绑定 UI 持有的原生窗口，表面独占其图形资源，原生窗口须在表面销毁后释放。

### 2.1 帧与窗口

- `VideoFrameView` 借用只读、顶行优先的 BGRA8 SDR 像素，忽略 alpha。解码侧帧所有者保证像素在 `present` 返回前有效。表面可将像素上传到自有资源，返回后不得访问借用的像素。上传或呈现资源在获协商尺寸及调整目标时准备，稳态使用固定数量。
- `present` 在访问像素前校验宽高非零、`stride >= width * 4`、实际长度覆盖最后一行像素，以及中间运算没有溢出。无效帧返回 `kInvalidArgument`。UI 在调用之前核对会话及协商代次，过期帧立即释放。
- `resize` 使用窗口客户区物理像素。任一尺寸为零时暂停呈现，恢复有效尺寸后可继续。用客户区内保持宽高比的最大居中矩形呈现画面，其余区域填黑。像素矩形尺寸向下取整后至少为 1，奇数余量留在右或下。UI 使用最近一次成功呈现的矩形及源尺寸，尺寸调整或表面丢失使旧矩形失效。坐标换算和远端映射版本由输入规格定义。

### 2.2 呈现结果与首帧

| 结果 | 含义与调用方处理 |
| --- | --- |
| `PresentedFrame` | 本次图形呈现请求被本地呈现后端接受，返回实际像素矩形。UI 可向 Session 报告当前协商代次的首帧。物理显示时间由 M1 实测 |
| `kUnavailable` | 暂停、目标遮挡或后端暂时不能接受本帧。UI 丢掉当前帧，保持最新帧槽可覆盖，在后续帧重试 |
| `kRenderSurfaceLost` | 图形设备或表面失效。UI 作废矩形并释放失效资源，重建后仅尝试呈现当前代次的新帧。未呈现的帧不能触发首帧确认 |
| `kInvalidArgument` | 帧描述无效，无图形调用，也不确认首帧 |
| `kNotSupported` / `kInternal` | 所需图形能力不支持或不可恢复的内部错误。UI 向 Session 报告错误，按 001 关断 |

`resize` 成功表示目标状态已更新，零尺寸也可成功。失败按上述资源错误处理。Decode → UI 最新帧槽容量为 1，未消费的旧帧可被覆盖。一次成功呈现只允许对对应的当前协商代次发出一次首帧通知，Session 复核代次后生成 `session.ready`。过期帧、仅解码成功、被遮挡或提交失败都不能确认首帧。M1 批准后 30 秒超时规则保持适用。

## 3. 不变量

- UI 使用最新的可呈现帧，丢弃过期帧。任何失败均不会确认首帧。
- `present` 返回后，表面仅持有自己的图形资源。解码帧的引用按所有权规则释放。
- 停会话时先停止帧交付，再释放当前帧、槽中帧及表面资源，UI 发带代次的退出确认。

## 4. 线程与资源

| 资源 | 所有者与上限 |
| --- | --- |
| 解码帧与最新帧槽 | Decode 写、UI 取，一槽覆盖。UI 只在调用期间持有当前帧 |
| 图形表面与目标 | UI 独占，调整尺寸和重建也在 UI 执行 |
| 首帧与退出通知 | UI 通过 001 已定义的按代次槽位通知 Session。UI 不等待 Session、Decode、Network 或下一次垂直同步 |

使用[线程模型](../../architecture/threading.md) §2.4 和 §2.9 的边沿。系统图形 API 和原生窗口操作位于 Windows 平台层。

## 5. 验收场景

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| RS-01 | 有 padding 的合法帧及过小 stride、缓冲不足、溢出尺寸、零尺寸帧 | 合法帧上传正确像素。无效输入返回 `kInvalidArgument`，无底层图形调用 |
| RS-02 | 16:9 帧呈现在更高或更宽客户区，随后调整为零尺寸再恢复 | 匹配居中矩形和黑边。调整后作废旧矩形，零尺寸不确认首帧，恢复后新矩形正确 |
| RS-03 | mock 图形后端依次报告暂不可用、设备丢失与成功 | 前两次无首帧通知。释放失效资源并重建，成功帧携带实际矩形且只确认一次 |
| RS-04 | 延迟 UI 消费并切换代次，投递旧帧和旧退出回执 | 只取最新的当前帧。旧帧不呈现，旧回执不推进新会话，缓冲引用恢复 |
| RS-05 | 首帧始终无法呈现，或后端报不可恢复错误 | 分别走 001 首帧超时或错误关断路径，未发 `session.ready` |
| RSH-01 | Windows 控制端真机呈现已知测试画面，调整尺寸、最小化并恢复 | 记录画面比例、首帧事件和恢复行为。按 001 M1H-04 另计可见延迟 |

## 6. 依赖与待决项

使用 Windows SDK 与现有测试框架。具体图形后端和解码输出接入见方案。UI 几何以物理像素为单位，DPI 与输入映射由后续输入契约衔接。

## 7. 并发自检

| 编号 | 约束 |
| --- | --- |
| T-01、T-02 | Decode 移交帧。UI 拥有图形对象，沿用 ④ 与 §2.9 回执边沿 |
| T-03 | 一槽覆盖，首帧和生命周期通知沿用 001 上限 |
| T-04、T-05 | 稳态复用资源。图形提交不能使 UI 等待其他业务线程或垂直同步 |
| T-06 | 按 001 顺序停会话。UI 释放本代次资源后确认退出 |
| T-07、T-08 | 新平台文件标注 UI 归属。沿用既有线程 |
| T-09 | RSH-01 记录后端及条件，M1H-04 记录端到端数据 |
