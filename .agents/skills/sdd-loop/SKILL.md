# SDD 开发回路

本仓库的强制顺序：**先规格，后测试，再实现，最后贴证据**。
[AGENTS.md](../../../AGENTS.md) 是总纲；本文件是每次任务都要走一遍的操作序列。

顺序不是形式。跳过前面任一步，后面所有“通过”都不可信。

## 第 0 步：判断任务类型

| 用户要什么 | 入口 |
| --- | --- |
| 新功能 | 第 1 步（新规格） |
| 改已有行为 | 第 1 步（改现有规格） |
| 修缺陷，行为不变 | 跳过规格，直接第 2 步写复现测试 |
| 改架构 / 线程 / 接口 | 第 1 步，且**先改文档再改代码** |

判断失误的代价：把架构变更当成普通功能做，会导致文档与代码分叉，下次没人敢信 `docs/`。

拿不准时先问用户，不要自行选一条路走。

## 第 1 步：规格

1. 读现有的 `specs/spec-*.md`，确认这件事是否已被覆盖。
   已覆盖就改那一份，不新建重复规格。
2. 没有就按 [specs/README.md](../../../specs/README.md) 的模板新建，
   文件名 `spec-<feature>.md`。
3. 填齐六节：范围、接口契约、不变量、线程与资源、验收场景、依赖与待决项。
   涉及多线程时补第 7 节（threading.md 的 T-01~T-09 自检）。
4. 验收场景必须编号（`XX-01` 形式），一条一个可断言的结果。
5. 跑 `python tools/check_specs.py` 确认结构合规。

**状态处理**：写完是 `status: draft`。**不要自己改成 `approved`**。
告诉用户规格已就绪，请其确认；用户明确同意后才改状态行。

## 第 2 步：红灯

按 [tdd](../tdd/SKILL.md) 执行。要点：

- 先只改测试文件，跑 `ctest --preset debug -R <用例名> --output-on-failure`。
- 确认失败原因是“缺这个行为”，不是编译错误或环境问题。
  编译失败不算红灯。
- 记下红灯输出，后面交付时要一起贴。

## 第 3 步：实现

- 只写到让测试通过，不加规格外的能力。
- 每轮先重跑目标用例，最后跑全量。
- 改动涉及热路径、队列、线程时，对照
  [docs/threading.md](../../../docs/threading.md) 第 5 节 T-01~T-09 逐条自检。
- 新增源文件必须有 `// Thread: <线程名>` 头注释，取值见 threading.md 第 1 节。

## 第 4 步：证据

声称“完成”之前，必须实际运行并贴出：

```bash
cmake --build --preset debug
ctest --preset debug --output-on-failure
```

输出要包含 `100% tests passed` 或具体失败项。**三类非业务用例也在其中**：

| 用例 | 失败意味着 |
| --- | --- |
| `spec.structure` | 规格状态行或章节不合规 |
| `arch.layers` | 依赖方向越界或线程归属缺失 |
| `core.assert.*` | 断言机制本身坏了 |

任一失败都算没完成，不能挑着贴。

同时报告：

- 新增/修改的测试用例编号，对应规格里的哪条验收场景；
- 未达标或未测的部分（如实说“未测”，不要写“应当可以”）；
- 证据落盘路径（`test-results/`）。

## 路由指令

用户可能在任务里带一句路由，例如：

> 先读 docs/threading.md 确认 Capture 线程边界，再按 AGENTS.md §5 的 TDD 循环实现。

按它执行，不要绕过。没有路由指令时，按本文第 0 步自行判断并**说明判断结果**。

## 硬性禁止

- 规格是 `draft` 时写功能代码。
- 测试第一次跑就通过，且说不清它为什么本该失败。
- 为了让测试通过而改断言、缩范围、加 `GTEST_SKIP`。
- 只贴通过的那部分输出。
- 声称完成但没有实际运行过 `ctest`。
- 自行把规格改成 `approved`。

## 反例：这几种“完成”都不成立

| 说法 | 问题 |
| --- | --- |
| “代码写好了，测试应该能过” | 没跑。 |
| “只有 smoke 失败，跟我的改动无关” | 无法证明无关，要么修要么给出证据。 |
| “规格后面补” | 顺序反了，实现已经迁就了记忆里的需求。 |
| “手动点过了，没问题” | 不可重跑，下次改动还要重来。 |

## 交接

需要提交时按 [git-commit](../git-commit/SKILL.md) 处理。
提交信息里引用规格文件名与验收编号，便于回溯。
